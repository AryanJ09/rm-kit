# rm-kit

A design system built on [shadcn/ui](https://ui.shadcn.com). shadcn supplies the behaviour; **every colour, size, radius and shadow comes from one token file** (`apps/v4/rm-style`). Storybook is the review surface.

This repository is a fork of the shadcn/ui monorepo (MIT, see `LICENSE.md`). Everything specific to the kit lives in `apps/v4`.

## Quick start (any computer)

Install Node 22 or 24 from https://nodejs.org, open a terminal, and run:

```bash
git clone https://github.com/AryanJ09/rm-kit.git && cd rm-kit && corepack enable && pnpm install && pnpm storybook
```

Then open http://localhost:6010. The first start takes about a minute.

## Run it

You need Node 22 or 24 LTS (`node -v`). pnpm is fetched by Corepack, which ships with Node 22 and 24. If `corepack enable` is missing or fails with a permissions error (common on Windows with a system-wide Node), run `npm i -g pnpm@10.33.4` instead, or use an administrator shell.

```bash
git clone https://github.com/AryanJ09/rm-kit.git
cd rm-kit
corepack enable
pnpm install
pnpm storybook
```

Open http://localhost:6010. Works the same on macOS, Linux and Windows (PowerShell or Git Bash). The first start also builds the workspace packages Storybook depends on, so allow a minute.

The install may print an "ignored build scripts" warning; it is harmless. Later starts also rebuild the workspace packages, which takes a few seconds.

Port 6010 busy? `pnpm --filter=v4 exec storybook dev -p 6011`.

The sidebar starts with **RM Kit** (the Figma-specified components), then **Examples** (a responsive dashboard), then the remaining shadcn components restyled with the same tokens.

## Checks

```bash
pnpm kit:check                    # token audit + kit typecheck
pnpm --filter=v4 audit:tokens     # every token resolves to a primitive; no raw values in RM Kit components
pnpm --filter=v4 typecheck:kit    # kit, stories and Storybook config; needs no generated files
pnpm --filter=v4 build-storybook
```

CI (`.github/workflows/ci.yml`) runs the same three on every push and pull request.

## How styling works

Three layers, each referencing only the one below it:

| Layer | Where | Example |
| --- | --- | --- |
| Primitives | `rm-style/theme.css` (`--ds-*`) | `--ds-color-accent-500`, `--ds-spacing-16` |
| Semantic roles | `rm-style/theme.css` (`:root`) | `--primary`, `--field-focus`, `--size-control-md` |
| Component tokens | `rm-style/components.css`, `fields.css`, `navigation.css` | `--badge-conservative-background`, `--field-height-md` |

Components use utilities such as `bg-primary` or `h-(--size-control-md)`, never raw values. To restyle the kit, change a primitive or a role; no component file needs to change.

## Folder map (`apps/v4`)

- `rm-style/theme.css`, `components.css`, `fields.css`, `navigation.css` – the token files. `theme.css` is the single entry; it imports the others.
- `rm-style/ui/` – the components. These replace shadcn's `styles/base-nova/ui` inside Storybook.
- `stories/` – Storybook stories. Files starting with `// Generated by scripts/gen-rm-stories.mjs` are generated from the shadcn demos; the others are hand-written and never overwritten.
- `stories/figma/` – state grids that mirror the Figma specs.
- `scripts/gen-rm-stories.mjs` – regenerate stories: `pnpm --filter=v4 gen:stories`.
- `scripts/audit-tokens.mjs` – the token audit above.
- `.storybook/` – Storybook config; `main.ts` points shadcn demo imports at `rm-style/ui`.

## RM Kit components

Button (Primary, Secondary, Text; sizes 40/48/56), Badge, Checkbox, Radio, Switch, Input, Textarea, Search, Dropdown, Date picker, Navigation item, Bottom navigation, Alert dialog, Dialog, Drawer, Message, Message scroller, Sheet.

Sizes share one scale across buttons and fields: sm 40, md 48 (default), lg 56. Icons use sm 16, md 20, lg 24.

## Conventions

- Font is Roboto only.
- Focus is always the blue field focus colour with the primary focus ring.
- Badges are static labels: no hover or focus styling.
- Do not add raw colours or numeric Tailwind spacing (`p-4`) to a kit component. Add a primitive or role, then reference it. `audit:tokens` fails the build if you do.
